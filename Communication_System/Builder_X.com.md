# Builder Voice

**Primary Surface**: X (@Quiznat)  
**Purpose**: Show momentum, experimentation, and proof of work  
**Audience**: Builders, designers, technologists, curious peers  
**Time Horizon**: Now / this week / this version

---

## Core Characteristics

- Process-forward
- Iterative
- Concise
- Concrete
- Slightly playful, but not performative

---

## What This Voice Does

- Announces versions, experiments, and POCs
- Shows what changed, not why it's profound
- Signals making, not selling
- Credits tools without evangelizing them

---

## What This Voice Avoids

- Grand claims
- Lore
- Deep explanation
- Emotional manipulation
- Audience fantasy

---

## Tone Dial

| Dimension | Level |
|-----------|-------|
| Energy | ◼◼◼◼◻ |
| Precision | ◼◼◼◼◼ |
| Hype | ◼◼◻◻◻ (intentionally constrained) |

---

## Builder Voice Template (X)

```
[Project] v[version]  
Short list of concrete changes  
Optional: one visual / emoji max  
Built with [tools], [time context]
```

---

## Example (De-Hyped, On-Brand)

> **It's a Match! v0.8.2**  
> Rare & Mythic cards, new UI sounds, Painted Bunting added.  
> Cardbacks polished + fixes. One week in.

_This keeps momentum without drifting into promo._

---

## X Articles (Long-Form)

X Articles allow deeper technical writeups on the same platform. Different mode, same voice.

**When to use Articles:**
- Technical deep-dives (architecture, AI implementation)
- Project retrospectives with context
- Historical/research content that supports a release

**How it differs from tweets:**
- Length constraint removed
- "Deep explanation" is allowed here (unlike tweets)
- Lore is acceptable when grounded in the build

**What stays the same:**
- Process-forward framing
- Concrete over abstract
- Credits tools without evangelizing
- No hype, no audience fantasy

See `Published_Fidchell_Twitter.md` for reference.
